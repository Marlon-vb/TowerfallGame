# skin/ — base body sprites (hand-generated chibi)

Source: poses generated by hand (ChatGPT image creator) from the canonical
prompt in `docs/CHARACTER_STYLE.md`, then normalized by
`tools/normalize_sprites.py` from raw exports in `art/incoming/<state>/`.

The base is a bald chibi in light grey shorts (the "skin" sheet = skin + the
default body). Hair/shirt/pants/accessory layers are deferred; the loader hides
them until their art exists.

## Format the loader expects

- **Frame size:** 64 x 64 px, transparent PNG. Character fills the frame and is
  bottom-aligned to a shared baseline (the normalizer guarantees this).
- **Layout:** one PNG per frame. Naming `<state>/east_<i>.png`, 0-based.
- **Direction:** `east` only (facing right). The scene mirrors it for left.
- **Color:** full color RGBA. The skin catalog entry is **non-tintable** for now.

## Frames present (all east)

| State | Frames | Files                  | Notes                          |
|-------|--------|------------------------|--------------------------------|
| idle  | 1      | east_0                 | neutral standing; held         |
| run   | 2      | east_0, east_1         | contact, passing; loops        |
| jump  | 1      | east_0                 | rising; held                   |
| fall  | 1      | east_0                 | descending; held               |
| dash  | 1      | east_0                 | horizontal burst; held         |
| shoot | 2      | east_0, east_1         | bow draw, release; play once   |
| die   | 1      | east_0                 | knocked back; held             |

These counts are mirrored in `Game/FileSpriteProvider.swift`. To add frames,
drop more PNGs into `art/incoming/<state>/` (named `0.png`, `1.png`, …), run the
normalizer, and bump `count` in the provider's `anims` table.

## Regenerating / adding poses

1. Generate the pose in ChatGPT using the per-pose template in
   `docs/CHARACTER_STYLE.md` (upload the approved base as a reference each time).
2. Save the raw export to `art/incoming/<state>/<n>.png` (any size, white or
   transparent background — no cropping needed).
3. `python3 tools/normalize_sprites.py` → writes uniform 64x64 frames here.
4. If frame counts changed, update `FileSpriteProvider.anims` to match.

## Known v1 quirks

- The bow is baked into the shoot frames (not a separate overlay yet). The draw
  frame has a small enclosed white pocket inside the bow curve (flood-fill can't
  reach a fully-enclosed area); harmless, reads as a bow. Split into a bow/arrow
  overlay later if we want it as its own cosmetic.
